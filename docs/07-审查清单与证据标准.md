# 文档 7：审查清单与证据标准

## 分层审查清单

### Critical（必须阻断合并）

- 空值与边界：空数组、除零、越界、未处理 null；
- 资源泄漏：未关闭的文件/连接/订阅；
- 并发竞争：先查后写无锁或事务；
- 注入：SQL 拼接、命令拼接、未转义输出；
- 异常被静默吞掉；
- `DOC_NOT_EXECUTABLE`（见文档 6）；
- `DUPLICATE_LOGIC`：新增了 `lib/`/`components/` 已存在的等价实现。
- `UI_DESIGN_DRIFT`：有前端页面时，实现的交互/视觉与项目 `DESIGN.md`（模板见文档 11）不一致——如既定的卡片单选被改成下拉、色值未用 token、新增已存在组件。阻断合并。

### Major（应修复，可带条件合并）

- 业务逻辑与需求不一致；
- 未复用已有组件/函数；
- 无意义测试（只测 getter/setter、断言恒真、只断言 mock 被调用）；
- 错误处理不规范；
- 硬编码（违反 lint 或 token 规则）。

### Minor（记录，不阻断）

- 命名、嵌套深度、注释与实现不匹配；
- 可读性建议。

## 审查瓶颈缓解（人审不过来怎么办）

整套体系把最终裁判押在「人类 Reviewer」身上，但人审是有限资源。三条缓解，务必落地：

1. **工具先圈、人再核验**（对齐 reviewdog 思路）：审查不再让人通读全部 diff，而是先跑 lint/类型检查/静态规则/测试在 diff 上圈出候选行，人类 Reviewer 只看机器已标记的点并核验真伪。**人的注意力从「通读」降为「核验机器圈出的候选」**。没接任何工具的裸 diff 通读，是要回避的做法。
2. **拆专职窄评审通道**（对齐 quickreview 思路）：不要让一个万能 Reviewer 每类都查一遍，拆成多条窄通道——每通道只盯一类（如「空值边界」「资源泄漏」「复用」「DOC_NOT_EXECUTABLE」），各自独立上下文。单点认知负荷低、拦截更稳。有独立执行者时优先这么拆。
3. **人只审「机器置信度之外」**：能被静态规则/脚本可靠判定的项（硬编码、DUPLICATE_LOGIC、语法）交给工具，只有需要语义/业务判断的项才占用人工。Reviewer 的产出从「逐条重查」变为「核验工具标记 + 审语义项」。

## 证据最小集（缺一即视为未完成）

1. 端到端命令及退出码：至少一条覆盖核心用户路径，`exit_code == 0`；
2. 关键断言输出片段：与验收标准逐条对应的输出行或响应体；
3. 产物哈希或文件清单：`changed_files` + 关键产物 SHA-256；
4. 范围声明：所有改动在 `allowed_files` 内，越界附人工批准记录。

## 防伪造规则

- **哈希封存**：`stdout`、关键产物、参数一并算 SHA-256，任何字段被改则封存失效；
- **跨模型交叉验证**：Reviewer 独立重跑核心命令，用自己产出的退出码对比；
- **Diff 一致性**：脚本检查 `changed_files` 与 `git diff --name-only` 完全一致；
- **禁止只读自述**：Reviewer 第一项操作是运行命令，不是读执行模型的总结。

## 审查输出模板

```yaml
task_id: T-042
decision: PASS | REJECT
findings:
  - severity: Critical | Major | Minor
    location: src/foo.ts:42
    risk: 空值未处理
    fix: 增加 null 检查并返回 400
    verify: npm test -- foo
pre_mortem: "如果三个月后这个功能失败，最可能的原因：……"
```

审查输出必须可直接转化为修复任务单，由 Orchestrator 打包派发，Reviewer 不直接改代码。

## 验证「Agent 的行为」，不只封存「输出的结果」

`stdout_sha256` 封存的是**命令跑出来的结果**，但没验证**这个命令/这次调用本身该不该那样跑**。对 AI 驱动的开发，自欺往往发生在「跑出去了，但脚本/提示词/参数本身就是错的」。补一条：

- 对**重复出现的 Agent 操作**（如固定的发版脚本、固定的测试命令、固定的证据包生成），建立**行为回归基线**：记录「输入参数 → 实际 stdout → 理由」的版本化快照；一旦 Agent 改了提示词、脚本或调用方式导致行为漂移（即使 stdout 仍 exit_code=0），由基线对比锁住。
- 参照 promptfoo 做法：给「Agent 的操作序列」做可回归测试，不只看单次结果。这让「连行为本身一起错了」这类深层自欺显形，而不仅靠事后哈希封存单点输出。

## 证据保留与审计

证据包写入 `evidence/<task_id>/`，随 PR 保留。每次状态跃迁记录审计条目：
`{task_id, from_state, to_state, gate_name, gate_result, evidence_hash, timestamp}`。
要求事后可逐条复核：任何人拿到证据包都能重算哈希并判断是否与跃迁记录匹配。
