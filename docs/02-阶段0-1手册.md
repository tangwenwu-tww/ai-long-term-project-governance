# 文档 2：阶段 0–1 手册（地基 + MVP）

## 阶段 0：地基（3–5 天）

**目标**：在写第一行业务代码前定下不可逆决策，建立最轻约束。

1. **定义核心假设**。一句话：“我们相信 ___ 用户会为了 ___ 使用 ___，因为 ___。”这是后续所有取舍的锚点。
2. **反向验证调研**。让 AI 列 2–3 个候选方案，重点论证**每个方案会在什么情况下失败**。输出一页纸：候选、硬门槛、结论。
3. **选型定稿并记录理由**。写入 `docs/decisions.md`：为什么选它、为什么排除其他、什么条件下会推翻。**作用是防止 AI 在后续会话中反复推翻已定决策。**
4. **建立 `AGENTS.md`**（用文档 1 模板，半页纸即可）。
5. **配置一条最小 lint**：只上 `color-no-hex` 级别规则，pre-commit 生效，CI 加 `--max-warnings 0`。不建 token 体系。
6. **写死 PoC 硬门槛**（任一触发即终止该方案）：
   - 数据无法合法使用；
   - 没有可行生产路径；
   - 安全对抗集出现成功攻击。
7. **一次性搭项目骨架，人工放行后再进功能开发**。方向定稿后，让 AI 用大任务一次性搭骨架（脚手架 + CI + lint/prettier + 基础测试框架 + README，目录按功能模块划分如 `features/`、共享组件独立目录），**此时禁止混入任何业务逻辑**；然后由人工审核骨架，确认目录清晰、依赖精简、无过度抽象、核心链路关键文件齐备，通过后才开始写第一行业务代码。**骨架未过人工放行，不进功能开发。**

**产出物**：核心假设、`decisions.md`、`AGENTS.md`、一条 lint、PoC 硬门槛清单、人工放行过的项目骨架。

**验收**：能回答“为什么选这个技术栈、什么情况下会换”，且 `AGENTS.md` 被 AI 会话首先读取。

**升级**：核心假设被证明可跑通 → 阶段 1。

## 阶段 1：MVP 验证（0→1）

**目标**：最快速度验证核心假设。**此阶段不建治理。**

1. **单 Agent + 自动检查与可复核证据**。阶段 1 不设人工或独立 Reviewer 合并门禁，不分角色、不建状态机、不并行 Worktree；作者自检不得标记为独立审查。高风险契约、不可逆决策和阶段跃迁仍需项目负责人批准。
2. **只写关键路径集成测试**。不写单元测试金字塔。验证“用户能不能走通核心流程”。
3. **任务单附检索命令**。每次实现新功能前附一条 `rg` 命令，要求先检索已有组件，并在回复中贴出结果。
4. **保留功能开关**。每个新功能包一层开关，坏功能能一键关掉。不做演练、不做清单。
5. **文档只记决策**。`decisions.md` 持续追加；不建 wiki、不写状态字段。
6. **执行常驻规则**：同一 Bug 连续 3 次失败即人工介入；同一错误纠正第二次即写入 `AGENTS.md`。

**此阶段明确砍掉**：状态机、证据包、评分卡与置信度分级、测试债扫描、文档过期检测、安全模式演练、多角色协作、Worktree 并行。

**产出物**：可运行的核心流程、关键路径测试、功能开关、增长的 `decisions.md` 与 `AGENTS.md`。

**验收**：核心假设被验证为真或假。为假 → 回阶段 0 换方向；为真 → 阶段 2。

**升级触发（任一）**：第一个真实外部用户；代码约 2 万行或模块超过 5 个；首次线上故障。
