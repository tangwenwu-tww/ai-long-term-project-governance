## 8.1 任务单模板

```yaml
task_id: T-XXX
title: ""
phase: 0 | 1 | 2 | 3 | 4
acceptance_criteria:
  - "空输入返回 400"
  - "正常输入返回 200 且字段完整"

  - src/module-a/
pre_implementation_search:
  commands:
    - "rg -l '<核心函数名或组件名>' src/ components/ lib/"
  evidence_required: "列出匹配文件及每个文件为何不可直接复用，或为何必须新增"
doc_type: how-to | adr | runbook | reference | none
doc_purpose: ""
```

## 8.3 ADR 模板

```markdown
---
type: adr
purpose: 记录 [决策主题] 的选择与理由
audience: 后续维护者
status: active
---

## 背景
（什么问题、什么约束）

## 选项
- A：优缺点
- B：优缺点

## 决定
选 [X]，因为 [理由]。

## 推翻条件
如果出现 [条件]，应重新评估并推翻本决策。

## 更新记录
YYYY-MM-DD 初版
```

## 8.4 PoC 评估报告模板

```markdown
---
type: adr
purpose: 记录 [方案] 的 PoC 结果与是否进入选型
audience: 决策人
status: active
---

## 成功标准（构建前固定）
| 维度 | 指标 | 阈值 | 测量方法 | 判定人 |

## 测试集
- 常规 60% / 困难 25% / 边界 15%；保留部分不调参

## 硬门槛结果
- 数据合法使用：通过/失败
- 生产路径：通过/失败
- 安全对抗集：通过/失败

## 评分与置信度
| 维度 | 得分(0-5) | 是否 ≥ 阈值 |

## 结论
PASS / FAIL / ITERATE ONCE / 换方案
```

## 8.5 Runbook 模板

```markdown
---
type: runbook
purpose: [故障/操作] 时的执行步骤
audience: 值班人
status: active
---

## 触发条件
（什么现象时看这份）

## 步骤
1. …
2. …

## 验证
（怎么确认恢复）

## 回滚
（失败时怎么退）
```

## 8.6 发版检查清单

```yaml
release_gate:
  - 本地测试全绿（范围：[module-a]）
  - 版本号已更新
  - 变更日志已生成

  - 高风险模块功能开关状态已确认
  # 任一失败 → 发版脚本拒绝继续
```
