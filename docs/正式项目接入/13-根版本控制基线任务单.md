# T-FOUNDATION-001：建立根版本控制基线

## 用途

在开始正式 Go 源码骨架前执行本任务。它只把当前方法论、文档和可复用源码纳入一个可恢复的本地 Git 基线，不连接远端、不开发安装器，也不改变两个独立实验仓库的历史。

## 执行边界

1. 文本修改必须使用补丁方式完成。
2. 不删除、移动或清理已有实验产物；只通过忽略规则阻止其进入根索引。
3. 根提交不得吸收两个独立实验仓库为 gitlink、submodule 或普通文件。
4. 不设置远端，不触碰两个独立仓库的 remote、分支、提交或工作树。
5. 下一张任务单只能冻结最小、可逆的 Go 骨架和测试入口；不得提前实现 `plan`、`apply`、`doctor`、状态机或信任逻辑。
6. 首次提交会把任务开始前已经存在的项目快照纳入版本控制；这些既有文件是基线内容，不代表本任务改写了它们。

```powershell
git -C experiments/cloud-runtime-matrix rev-parse HEAD
git -C experiments/installer-lifecycle-matrix status --short
git -C experiments/installer-lifecycle-matrix rev-parse HEAD
```

## 常见错误 / 注意事项

- 根 Git 看不到被整体忽略的实验仓库内容是预期行为；它们由各自仓库恢复。
- `.gitignore` 不会删除磁盘文件，也不是实验数据清理操作。
- 本任务的基线提交只表示“可恢复起点已建立”，不表示 Go 产品骨架或可信发布已经完成。
