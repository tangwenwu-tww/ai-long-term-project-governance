# T-HALT-001 R1：阶段 1 同签名三次自动止损契约

## 用途

修复 `T-E2E-001 e2e-001-a001` 暴露的 E `CAPABILITY_MISSING`：安装后的目标项目必须只依赖本地治理实例，即可持久化记录 attempt 成败与 failure signature，在连续三次相同失败后进入 `HALTED_FOR_HUMAN`，并对第四次写入做机器拒绝。

本任务只冻结公共契约并在批准后建立红灯黑盒测试；不在本任务实现生产代码、运行三平台 CI 或创建 E2E `a002`。

## 当前事实

- 当前 `0.3-draft` apply 只安装 agent entry、instance/phase 和两个 schema；`instance.json.resources.runtime_root` 只是路径声明，没有可执行文件。
- 正式 Go CLI 已有 plan/apply/evidence，但目标项目断网且禁止访问方法论源仓库时，不能依赖这个外部开发位置。
- Python PoC 的 `record-attempt` 已验证“成功清零连续计数、第三次停止、已停止任务拒绝继续”，但 Python 不是正式 runtime，其可变 `state.json` 也不是正式权威源。
- 阶段 1 不启用阶段 3 完整任务状态机、review 或通用事件链；本任务只实现五阶段常驻的最小止损切片。

## R1 候选契约

### 1. 安装契约 0.4-draft 与本地 runtime

安装 manifest 升级为精确版本 `0.4-draft`，旧版本 fail-closed。实例资源新增必填逻辑 ID `runtime_entrypoint`：

- Windows amd64 默认 `.ai-governance/runtime/aigov.exe`；
- Linux amd64 与 macOS arm64 默认 `.ai-governance/runtime/aigov`；
- custom layout 可调整安全项目相对路径，但文件名必须保持平台可执行形式。

plan 将当前正在运行的、与目标平台一致的 `aigov` 原生可执行文件作为 tool-owned prepared bytes：

- 缺失时输出 `CREATE runtime_entrypoint`，带完整 SHA-256；
- 已存在且摘要一致时 `NOOP managed_content_matches`；
- 存在但摘要不同、不是普通文件或任一父路径 link-like 时 `CONFLICT`/fail-closed。

`instance.json.resources.runtime_entrypoint` 写入有效项目相对路径；`managed_files.runtime_entrypoint` 写入可执行文件原始字节 SHA-256。apply 继续使用同目录 temp、Sync、hard-link no-replace 和事务回滚；不从网络下载 runtime，不猜测其他平台产物。

### 2. record-attempt 命令

安装后的 runtime 必须离线支持：

```text
<runtime_entrypoint> record-attempt \
  --project <root> \
  --task-id <task_id> \
  --attempt-id a001 \
  --exit-code <integer> \
  [--signature-sha256 <64hex>]
```

语义：

- `exit-code == 0` 代表成功，`signature-sha256` 必须缺省，并把连续失败签名/计数清零；历史总失败数不回退。
- `exit-code != 0` 代表失败，必须提供 64 位小写 `signature-sha256`；只保留摘要，不把可能含密钥的原始错误文本写入仓库。
- 新失败签名与上一个连续失败签名相同时计数 +1；不同时从 1 重新计数。
- 第三个连续相同失败记录必须成功持久化，状态进入 `HALTED_FOR_HUMAN`，命令返回 3。
- 已停止任务的第四次及后续 `record-attempt` 返回 3 和 `E_TASK_HALTED`，不创建新记录，不修改缓存。
- 本切片不实现 Agent 可调用的 unhalt/reset；必须升级人工，并由后续可信批准契约决定如何恢复。

### 3. attempt 顺序与不可变记录

- `attempt-id` 必须精确匹配 `aNNN`，从 `a001` 开始严格连续递增；跳号、倒退或复用返回 `E_ATTEMPT_SEQUENCE`。
- canonical source 为 `instance.json.resources.task_audit_store/<task_id>/attempts/aNNN.json`，每份记录至少包含 `schema_version`、instance/task/attempt ID、exit code、`SUCCESS|FAILURE`、nullable signature SHA-256、UTC RFC3339 秒级时间和 `record_sha256`。
- `record_sha256` 是移除自身后的整个记录 canonical JSON 字节 SHA-256；磁盘文件为 canonical JSON + LF。
- 发布使用同目录 temp + Sync + hard-link no-replace；每 task 使用 exclusive lock，锁存在时返回 `E_CONCURRENT_UPDATE`。
- 任意历史记录文件缺号、文件名/内容不绑定、摘要错误、重复 key、非 canonical 或特殊对象均返回 `E_HALT_AUDIT`，不得根据损坏历史继续计数。

### 4. 可重建状态与独立查询

`instance.json.resources.task_state_cache/<task_id>.json` 只是可删除缓存，不是权威源。每次记录前必须先重放全部不可变 attempt 记录；记录发布后再原子替换缓存。如果记录已发布但缓存更新失败，记录仍然有效，下次命令重建缓存。

本地 runtime 还必须支持只读：

```text
<runtime_entrypoint> halt-status --project <root> --task-id <task_id>
```

stdout 为单行 canonical JSON，至少包含 `status: EXECUTING|HALTED_FOR_HUMAN`、`last_attempt_id`、`consecutive_signature_sha256`、`consecutive_count`、`total_failures`。非停止返回 0，已停止返回 3；查询不修改任何文件。

### 5. 阶段边界

- 这是阶段 1 最小 failure-attempt ledger，不是阶段 3 的 PLANNED → CLOSED 通用任务状态机，不写入虚构 review/close 事件。
- 后续启用完整 event chain 时，必须以显式迁移计划将这些已验证 attempt 记录纳入新事实，禁止静默删除或当作未发生。
- 本任务不实现阶段 4 “不同签名累计十次”总失败上限，但保留 `total_failures` 事实以便后续升级。

## 黑盒红灯测试矩阵

批准后的 `tool/contracttest/halt_test.go` 必须能编译，并在当前 `0.3-draft` 实现上因缺少 runtime/`record-attempt` 而稳定失败：

1. plan/apply 创建平台 runtime entrypoint，其字节与执行 apply 的可执行文件摘要一致；新实例重复 apply 为 NO_CHANGES。
2. runtime 在断网、cwd 为目标项目且不读取源仓库文件时可运行 `record-attempt`/`halt-status`。
3. 两次相同失败返回 0；第三次返回 3 且状态为 `HALTED_FOR_HUMAN`；第四次返回 3/`E_TASK_HALTED` 且文件树不变。
4. 失败、成功、同签名失败序列证明成功清零；不同签名证明连续计数重置为 1。
5. attempt 跳号/复用、错误 signature 组合、路径逃逸、symlink/junction/reparse 和特殊文件 fail-closed。
6. 历史 record 的内容、摘要、文件名、编号或 canonical bytes 被篡改后，`record-attempt` 与 `halt-status` 均返回 `E_HALT_AUDIT`。
7. 删除或任意改写 state cache 后，从 attempt ledger 得到逐字节一致的重建结果。
8. 同 task lock 竞争返回 `E_CONCURRENT_UPDATE`；不同 task 的记录互不阻塞。
9. runtime bytes 被外部改写后 plan 为 CONFLICT，不在 apply 时静默覆盖。
10. Windows amd64、Linux amd64、macOS arm64 运行相同 portable tests；平台链接/属性用例分别报告。

## 实现前检索结论

- PoC 的可复用事实只是计数语义和退出码 3；Python 文件、可变总 state 与阶段 4 总失败上限不复制到正式 Go 实现。
- 当前 plan/apply 已有 tool-owned prepared bytes、SHA-256、路径安全、exclusive install lock、hard-link no-replace 和进程内回滚，可复用于安装当前原生可执行文件。
- `instance.json` 已声明 `runtime_root`、`task_state_cache` 和 `task_audit_store`，但当前没有精确 runtime 文件资源、managed hash、attempt record 或状态重放实现。
- E2E E 的 PASS 条件要求“安装实例本地可执行”；仅向本方法论源仓库的开发 CLI 添加命令，不会修复 `CAPABILITY_MISSING`。
