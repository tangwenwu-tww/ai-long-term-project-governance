## 工作流与验证逻辑

### 工作流静态检查

工作流与任务单要求一致：

- matrix 明确使用 `windows-latest`、`ubuntu-latest`、`macos-latest`，`fail-fast: false`；
- 权限仅为 `contents: read`；
- 使用 `actions/checkout@v5`、`actions/setup-go@v6`、`actions/setup-node@v6`、`actions/upload-artifact@v6`；
- Go 版本为 `1.27.x`、`check-latest: true`、`cache: false`；Node 固定 `26.13.1`；
- Windows 对 Go/Node build 和 run 逐项保存 `$LASTEXITCODE`，非 0 立即失败；
- Unix 使用 `set -euo pipefail`，任何 build/run 失败都会在证据写入前终止，只有成功路径才把退出码记录为 0；
- 三平台证据包含 runner OS/arch、commit、build/run 退出码、程序 JSON 输出、大小、SHA-256 和签名状态；
- 每个 matrix job 只上传对应 JSON，缺文件即失败，保留 30 天。

### Go/Node 向量一致性

Reviewer 从两份源码分别提取事件 preimage、预期 SHA-256、INIT payload、owner 公钥和签名，五项逐字一致。独立对 preimage 的 UTF-8 字节计算得到：

`81588443ac9948f2eda8f0269294b006d10be5d8f4e7dcf4bb23ef17a88d624d`

与两份源码的 expected hash 相同。两份程序都在 hash 或 Ed25519 校验失败时返回非 0。两份 SEA 配置均可解析，固定 `main.js`、CommonJS、关闭 snapshot/code cache，并分别输出 Windows `.exe` 与 Unix 文件。

### 本地实际运行

系统 Node v24.19.0 直接运行 `node/main.js`，退出码 0，输出 hash match 与 owner signature 均为 true。

Reviewer 进一步把 canonical Node 源码和 Windows SEA 配置复制到随机系统临时目录，使用前序已校验的便携 Node `v26.13.1` 构建 SEA，并在子进程 `PATH` 为空时从绝对路径执行：
