## 独立验证方法

本轮使用 Node.js v24.19.0 内置 `crypto`，没有调用作者脚本：

1. 用独立递归 key-sort canonicalizer 从解析后的对象重新生成本测试向量涉及的 RFC 8785 JCS 字节，而不是直接信任文档给出的 preimage 字符串。
2. 对两条事件的 JCS UTF-8 字节重新计算 SHA-256。
3. 从文档中的 RFC 8037 OKP JWK 建立 Ed25519 公钥，用 Node 原生验签验证 INIT、ROTATE、REVOKE 的五个签名。
4. 独立检查签名集合、排序规则、payload 篡改和事件优先缓存恢复语义。

### 缓存崩溃恢复

独立 reducer 先按 INIT→ROTATE→REVOKE 生成正常 trust 语义状态，再模拟“REVOKE 事件已提交、缓存仍停留在 ROTATE”的崩溃点。丢弃旧缓存并从完整 canonical 事件序列重放后，得到与正常路径一致的 key 状态与 nonce 消费状态。这与 03 第 610–635 行规定的“事件先提交、缓存仅为可重建派生物”一致；事件前崩溃保持旧状态，事件后崩溃不得回滚事件，语义唯一。
