## Critical findings

### C-1 `DOC_NOT_EXECUTABLE`：canonical README 缺强制 frontmatter 和可复制运行方式

- **位置**：`experiments/delivery-runtime/README.md:1`
- **风险**：根 `AGENTS.md` 要求每份文档以合法 `type/purpose/audience/status` 开头，文档 6 又要求 how-to 提供最小可运行示例。该 README 是报告明确列出的 canonical source，却直接从标题开始，只描述两个源码文件，没有告诉后续 Reviewer 如何校验归档、使用固定 Node 26、构建三平台或执行空 PATH 检查。三个月后读者必须从聊天/报告反推命令，命中 `DOC_NOT_EXECUTABLE`。
- **修复**：增加合法 frontmatter（建议 `type: how-to`、明确 purpose/audience、在实验完成前保持合适 status），并写出可复制的工具链哈希检查、三种 build、Windows 空 PATH 运行和仅检查跨平台 magic 的命令；明确输出目录是 ignored、Go 未验证且本文不代表正式安装器。
- **验证**：全新 Reviewer 只读取 README 和 canonical source，能在隔离目录复现本记录的三组哈希/大小/边界结论。

## Major findings

### M-1 报告的 `changed_files` 与任务 `allowed_files` 不一致

- **位置**：`06-交付运行时实验任务单.md` 的 `allowed_files`；`07-交付运行时实验报告.md` 的 `Changed files`
- **风险**：任务只允许 `experiments/delivery-runtime/**` 和 07 报告，但报告自列的变更还包含 06 任务单。若 06 是派单方在 attempt 开始前冻结的输入，它不应计入 Executor 的 `changed_files`；若它在执行中被作者修改，则属于越界。当前没有 Git 或独立基线，Reviewer 无法证明哪一种发生，因此范围证据不满足“changed_files 与 allowed_files 一致”。
- **修复**：不要追溯性扩大本 revision 的 `allowed_files`。提供可验证的 attempt 起点/派单记录，证明 06 在 Executor 开始前已冻结，并把 Executor `changed_files` 更正为允许范围内文件；若确实由 Executor 修改，则创建新的任务 revision/人工范围批准，说明原因后重新执行证据链。
- **验证**：下一轮 Reviewer 能从不可变任务 revision 与变更基线重算实际 changed files，结果全部满足原始 allowed_files。

## Minor findings

### m-1 Go 三次失败缺少独立 stdout/哈希封存

- **位置**：`07-交付运行时实验报告.md`“Go”与“失败与恢复记录”
- **风险**：报告给出了三条命令、错误摘要和 winget 错误码，足以支持“未验证”分类，但没有保存三次原始 stdout/stderr、时间和哈希。网络失败不可稳定重放，后续 Reviewer 只能验证当前仍无 Go，不能证明历史三次 failure signature 完全相同。
- **修复**：下一次获取工具链时，把每次命令、UTC 时间、退出码、规范化 stdout/stderr 和 SHA-256 写入实验 evidence；失败达到三次时封存停止决定。
- **验证**：Reviewer 能从 evidence 独立判断三次是否同一 signature，而不是依赖报告摘要。
