# T-EVIDENCE-002：机器可复核证据生产实现

## 用途

在 `EVIDENCE-001-R1` 已获批准且红灯基线已以提交 `4285beb` 封存后，实现实验性 `aigov evidence begin/collect`，使无 Git 目标项目也能机器生成完整命令、退出码、stdout/stderr 摘要、内容变更清单和逐条验收映射。

本任务只让 `TestEvidence` 红灯转绿；不实现 `T-HALT-001`、`submit-evidence`、review gate、三平台 CI 或 E2E `a002`。

## 实现前检索结论

- `internal/cli` 已固定 feature flag、退出码、JSONL 诊断和 canonical stdout 的表面，可复用调度方式。
- `internal/plan` 已有 slash-normalized 路径、`Lstat` + `EvalSymlinks` 的 link-like 检测思路，但实现未导出；evidence 将在自己的读取边界保持同等 fail-closed 语义，不复制 plan 业务逻辑。
- `contracttest` 已提供跨平台 CLI 构建与 stdout/stderr 捕获；`evidence_test.go` 已冻结生产实现的可观测结果。
- 必须新增且封装在 `internal/evidence` 的闭包是：严格 request 解析、instance resource 解析、不 follow 项目快照、begin receipt 绑定、命令预检/捕获、内容 diff、allowed matching 与不可覆盖发布。
- R1 的 `expected_exit_code` 与 acceptance mapping 意味着机器以“实际退出码等于预期值”为验证条件；契约中“命令非零”的表述按“不等于 `expected_exit_code`”执行，以与已批准 request 字段和红灯测试一致。

## 明确不做

- 不修改 install manifest/instance manifest contract version，不将 evidence schema 加入 apply managed files。
- 不保留原始 stdout/stderr，不实现 redaction 或 blob 归档。
- 不建立任务状态机、失败计数、自动止损、review 或 phase 跃迁。
- 不读取 `F:\oioi`，不复用既有 E2E 隔离副本，不运行三平台 CI。
