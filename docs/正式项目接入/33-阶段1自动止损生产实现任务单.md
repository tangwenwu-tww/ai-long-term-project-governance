# T-HALT-002：阶段 1 自动止损生产实现

## 用途

在 `HALT-001-R1` 已批准且红灯基线已以提交 `eefebbf` 封存后，升级安装契约到 `0.4-draft`，把当前平台原生 `aigov` 安装到目标项目，并实现 `record-attempt`/`halt-status`、不可变 attempt ledger、可重建 cache、第三次停止与第四次拒绝。

本任务只让 `TestHalt` 红灯转绿；不实现 unhalt、阶段 4 总失败上限、通用任务状态机，不运行三平台 CI 或 E2E `a002`。

## 实现前检索结论

- `PreparedFile` 已携带精确 bytes 且 apply 已有 sibling temp、Sync、hard-link no-replace、exclusive install lock 和 CREATE/UPDATE 回滚；必须扩展每文件 final mode，不得把所有 managed files 都 chmod 0755。
- 当前 plan 的 canonical instance/golden/schema hash 在多处固定 `0.3-draft`；runtime bytes/hash 随当前构建产物变化，测试必须从 `cliPath` 动态重算，禁止维护每次源码改动就失效的二进制固定摘要。
- `instance.json` 已声明 `runtime_root`、`task_state_cache`、`task_audit_store`，但需新增精确 `runtime_entrypoint` resource 与 managed hash。
- `internal/evidence` 有可复用的 strict JSON、canonical JSON、安全相对路径、link-like 检测和 no-replace 思路；止损业务应独立放在 `internal/halt`，不复制 evidence 业务状态。
- PoC 只提供计数语义；正式实现以不可变单 task ledger 取代可变全局 state，并在每次写入前完整重放。

## 明确不做

- 不实现 unhalt/reset 或任何能让 Agent 自行解除 `HALTED_FOR_HUMAN` 的入口。
- 不实现阶段 4 不同签名总失败上限，不建通用任务状态机或 review gate。
- 不从网络下载 runtime，不在一个平台产生或猜测另一平台二进制。
- 不读取或修改 `F:\oioi`，不运行三平台 CI，不创建 `a002`。

## 实现结果与验收对应

- install/instance schema、manifest fixtures、plan/apply 输出与调用方已统一为精确 `0.4-draft`；旧 `0.3-draft` 继续由 contract-version 校验 fail-closed。
- plan 从当前普通原生可执行文件读取字节，生成平台 `runtime_entrypoint` 的 CREATE/NOOP/CONFLICT、instance resource 与 managed SHA-256；apply 对该文件使用 Unix `0755`，其他新文件保持 `0644`。
- `internal/halt` 实现严格参数/instance/安全路径校验、每 task exclusive lock、严格连续 immutable ledger、canonical JSON + LF、`record_sha256` 重算、完整 replay 与非权威 cache。
- 安装后的 runtime 已由黑盒测试在独立目标目录执行；同签名第三次失败写入后返回 3，第四次返回 `E_TASK_HALTED` 且文件树不变；成功与不同签名重置、ledger 篡改和 cache 删除/伪造用例均通过。
- 本轮只完成 Windows 本地验证；未运行三平台 CI 或 E2E，因此 E 只能记为“修复能力已实现、待复验”，不能改判 PASS。
