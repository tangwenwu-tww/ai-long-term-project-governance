# T-DELIVERY-005：安装、升级与回滚对比实验任务单

## 任务边界

本任务只比较 Go 原生可执行文件与 Node SEA 承载同一安装器协议时的行为与交付成本，不实现正式产品安装器，不形成最终技术选型，也不创建 `docs/decisions.md`。

## 固定实验模型

- `v0` 与 `v1` 各包含一个工具拥有的 runtime 文件和版本化 manifest。
- `AGENTS.md` 代表项目事实，只检查存在性和保留性，安装器不得覆盖。
- manifest 保存当前版本、工具文件相对路径、SHA-256 和最近一次可回滚快照。
- 冲突定义：manifest 记录的工具文件哈希与磁盘当前哈希不同。
- rollback 只恢复最近一次成功升级前的工具文件，不回滚项目事实。

## 签名边界

没有受信任的 Windows 代码签名证书、Apple Developer ID 与 notarization 授权时，只能记录 `unsigned` / ad hoc 事实。禁止生成自签名证书后声称正式签名发布通过；可信签名另设发布实验。

## 停止条件

- 两个候选开始使用不同验收标准时停止。
- 测试为了通过而读取候选内部状态、绕过公开命令时停止。
- 同一 failure signature 连续三次时停止并升级人工。
- 需要创建正式产品骨架、根 Git 或 `docs/decisions.md` 时停止。

## 不证明什么

- 不证明真实证书签名、公证、包管理器发布或企业终端放行。
- 不证明完整三方合并；本轮只验证“工具文件冲突停止、项目事实不覆盖”。
- 不证明最终交付技术已经选定；结果还需进入 04 的硬门槛、评分和人工定稿。
