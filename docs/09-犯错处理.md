# 文档 9：AI 重复踩坑怎么处理

## 用途

当某 AI Agent **同一个错误连续犯第二次、第三次**，而你发现“口头提醒 / 写文档说‘注意点’”都不管用时，照这份文档分级处理。它把「踩坑即规则」（文档 0 常驻规则 #2）落成可执行的三级跑表。

**核心一句话：AI 同一个错犯第二次，就别再跟它说“注意点”了，没用。得想办法让它“想犯也犯不了”。**

## 不适用

- 这只是**偶发一次**、没重复的错 → 不需要升级，随手纠正即可。
- 本项目是纯方法论，不在一套真实产品线内跑 → 不需要自己建坑库或拦截脚本，但读者自己的项目需要。

## 怎么用

### 先判断：算不算“高频”

同一个错 **连续出现 2–3 次** 就算高频。不用精确计数，感觉「又是这个毛病」就够了。

### 按次数分级处理，越来越狠

| 第几次 | 动作 | 具体做法 |
|---|---|---|
| 第 1 次 | **记下来** | 知道它爱犯这个错，先留意，不急着大动 |
| 第 2 次 | **写进规则文件** | 写入 `AGENTS.md`（如“本项目禁止在组件内直接写请求，必须走 api/ 层”），让 AI 下次开工前读得到 |
| 第 3 次 | **上机器拦截** | 光写规则已不管用，必须让“犯错”变成“会报错”，任选其一：lint 规则（一犯就报错，CI 挡合并）、审查清单加一条（审查模型看到就标红）、任务单加必填项（不填算没做完） |
| 再犯 | **停下来换人** | 别让 AI 自己修了：换个人看、换模型、把任务拆小；实在不行这个功能就别要了 |

### 关键在“第 2 步到第 3 步”

很多人卡在「我写了规则啊，它怎么还犯」。因为 **写在文档里的规则，AI 在长对话里会忘**。只有把它变成「会报错的检查」，才是真的拦住了。

**一句话：规则写在纸上没用，得让它变成会亮红灯的东西。**

## 常见错误 / 注意事项

- **不是所有坑都能上机器拦**：能用规则卡住的（硬编码、重复实现、写垃圾测试）→ 上 lint、审查清单、脚本；靠“理解”才能发现的（方案方向错、越修越乱）→ 别加规则，直接停下来换人换思路；AI 就是做不好的（特别复杂的重构）→ 换模型、把任务拆小、加人工检查点。
- **别只靠嘴提醒**：同一错犯第二次就说明提醒无效，直接进规则；第三次直接进机器拦截。
- **随手记，定期清**：每次 AI 犯错随手记一笔；同一个错出现第二次就写进规则文件；每周花十分钟把能自动拦的规则变成 lint 或检查；每月看一眼规则文件，没用的删掉，别让它变成没人看的长文。
