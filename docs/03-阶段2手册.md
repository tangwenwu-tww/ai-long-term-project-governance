# 文档 3：阶段 2 手册（过渡加固）

**进入条件**：阶段 1 验收通过，且至少一个升级触发信号出现。

## 步骤

1. **引入两角色协作**：执行模型实现 + 独立审查模型复核。审查模型用独立上下文，作者不能审自己。不建四角色、不建状态机脚本。
2. **建立 Major 级审查清单**，先上三条：
   - 业务逻辑是否与需求一致；
   - 是否复用已有组件；
   - 异常是否被静默吞掉。
   （Critical 级逐步补，见文档 7。）
3. **测试升级到两层**：关键路径集成测试 + 核心模块单元测试。暂不追求 70/20/10。
4. **检索升级为结构化字段**：任务单加入 `pre_implementation_search`，要求 AI 把检索命令和“为何不可复用”的结论写入任务单。缺失即视为任务未完成。
5. **Worktree 轻并行**：最多 2–3 个，用于“主线 + 实验分支”。命名规范固定，定期 prune。
6. **发版加程序硬校验**：本地测试全绿、版本号已更新、变更日志已生成，任一失败则发版脚本拒绝继续。
7. **文档加 `status` frontmatter**：至少区分 `draft` / `active`，AI 不得以 `draft` 文档为实现依据。

**产出物**：两角色流程、Major 审查清单、两层测试、结构化任务单模板、发版脚本、带状态文档。

**验收**：能在不破坏已有功能的前提下完成 3 次以上迭代；审查模型能稳定拦截 Major 级问题。

**升级触发**：团队超过 1 人或并行 Agent 会话超过 3 个；同一模块被 3 个以上功能复用；出现合规/合同/SLA 需求。
