# 文档 5：阶段 4 手册（长期运营与止损）

**进入条件**：阶段 3 完成，且存在需长期承担责任的模块。

## 步骤

### 1. 疑难 Bug 止损

| 条件 | 阈值 | 动作 |
|---|---|---|
| 同一 failure signature 连续失败 | 3 次 | HALT，升级人工 |
| 所有签名合计硬上限 | 10 次 | HALT，升级人工 |
| 停滞：连续 3 轮文件集相同且 diff < 10% | 3 轮 | 回滚到干净基线，切换根因分析；仍无进展则升级 |
| 触碰范围外文件/公共 API/DB schema/安全策略 | 任意一次 | 立即 HALT，零重试预算 |

升级时携带完整 failure memory：每次签名、假设、实验、结果、当前 diff、已排除根因列表。

### 2. 多模型独立根因分析

人工介入后，让多个强模型**独立**给出根因假设，人工对比置信度。若置信度普遍极低，或修复成本超过功能价值 → **果断砍功能或换替代方案**。

### 3. 安全模式清单化

为每个高风险模块预留功能开关；准备三种 containment：

- **Kill switch**：全局硬停；
- **影子模式**：接收流量记录输出，不作用于用户；
- **功能级禁用**：只关问题功能，系统其余部分正常。

回滚清单必须覆盖：模型/Agent 配置、工具权限、提示词版本、功能开关状态。

### 4. 安全模式演练

每个高风险模块每年至少一次，新增高风险模块首次发布前完成一次桌面推演或实际切换。通过标准：

| 检查项 | 标准 |
|---|---|
| 切换时间 | ≤ 约定 SLA（如 5 分钟） |
| 用户可见错误 | 0 个未预期，或 ≤ 基线 + 阈值 |
| 数据完整性 | 无写入丢失、无状态污染 |
| 回滚覆盖 | 配置/权限/提示词逐项勾选 |
| 恢复时间 | ≤ 约定 SLA |
| 可审计 | 操作、时间戳、触发条件、操作人全部落盘 |

**未通过演练的开关不得写入发布清单。**

### 5. 规则沉淀与复核

`AGENTS.md` 持续增长；每季度复核：规则是否仍有效、是否冲突、是否有规则从未被触发（从未触发考虑删除）。

### 6. 主动降档

项目进入维护冻结或砍掉产品线时，主动关掉不再产生收益的闸门（停用部分 E2E、合并审查角色、简化状态机），避免治理成本拖死团队。

### 7. 功能级止损：砍功能三问

前面的止损针对**单个疑难 Bug**；功能越堆越多，还要定期在外层裁掉**整个维护成本失控的功能**。每季度对候选项问三件事：

| 问 | 判定 |
|---|---|
| 过去 3 个月被修改过几次？ | 频繁修改 = 设计有问题 → 记负分 |
| AI 在这个功能上踩过几次坑？ | 踩坑多 = 抽象不够或边界不清 → 记负分 |
| 用户实际使用率多少？ | 低使用率 + 高维护成本 = 候选砍掉 |

三问累积三分即进「砍掉候选」，人工拍板砍或重构，别让一个功能无限累积维护成本。

**产出物**：止损规则、根因分析记录、安全模式清单与演练记录、功能砍掉候选清单、规则复核日志、降档决策记录。

**验收**：任一高风险模块可在 SLA 内进入安全模式并恢复；任一疑难 Bug 在阈值内被止损或砍掉。
